### Added
- Installed apps are LLM principals (#613). A catalog app that calls the model API declares `install: {llm_access: true}` (open-webui is wired as the reference) and install mints it its own LiteLLM key bound to `app:<app_id>`, scoped to a model allowlist (`install.llm_models`, defaulting to the `default` chat alias), and injects `OPENAI_BASE_URL` / `OPENAI_API_KEY` into the app's container env — instead of every app holding one shared token that reaches every model.
- Per-app model permissions surface: `GET`/`PUT /api/apps/{app_id}/llm-access` reads and re-scopes an app's allowlist (writes are admin-only), plus `POST /api/apps/{app_id}/llm-access/rotate` to mint a fresh key. A re-scope keeps the key value, so a running app picks up the new scope without a restart.
- The allowlist is enforced on both credential surfaces — the LiteLLM `custom_auth` hook and the in-process LLM gateway (new caller kind `app`) — because both read the same keystore row. An app principal is exempt from the per-agent LLM budget, since it is not an agent.
