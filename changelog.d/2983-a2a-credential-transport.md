### Fixed
- A2A bus send no longer forwards the caller's registry JWT over a remote cleartext `http://` transport. The credential is a no-expiry bearer token that authorises its holder as the agent until revoked, so it is now only sent over HTTPS or plain HTTP to a loopback host (the default co-located bus). A remote `http://` bus still receives the message unverified — the same degraded state every unauthenticated proxy send is already in — but the secret is withheld and `credential_forwarded` reports `false` instead of a 200 reading as "the bus could verify this". Added `_credential_transport_is_private` and a test asserting a loopback `http://` bus receives the credential while a remote `http://` bus does not (#2983, fix-forward of #2981).
